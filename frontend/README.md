# Konditer Plan — Система управления кондитерским производством

Полнофункциональная система управления кондитерским производством с автоматическим планированием, управлением ресурсами и отслеживанием заказов.

---

## Технологический стек

### Frontend
- **React 18** — UI фреймворк с функциональными компонентами и хуками
- **TypeScript** — типизированный язык для повышенной надёжности
- **React Router v6** — навигация между страницами
- **Fetch API** — синхронизация с backend через REST API
- **CSS3** — стилизация с поддержкой CSS Grid для расписания

### Backend
- **FastAPI** — асинхронный веб-фреймворк на Python
- **SQLAlchemy ORM** — работа с базой данных
- **PostgreSQL** — реляционная СУБД
- **Uvicorn** — ASGI сервер для запуска приложения

## Backend архитектура

### Слой API (app/api/)
- **REST endpoints** для каждой сущности (GET, POST, PUT, DELETE)
- **CORS middleware** для доступа с фронтенда
- **Автоматическая валидация** входящих данных

### Слой Services (app/services/)
- **BaseService** — базовый класс для всех сервисов
- **PlanningService** — автоматическое планирование заказов на основе доступных ресурсов
- **ValidationService** — валидация данных перед сохранением в БД

### Слой Repositories (app/repositories/)
- **BaseRepository** — базовый класс с операциями CRUD
- **Специализированные методы** для поиска по конкретным полям
- **Безопасное удаление** с каскадным удалением связанных данных

### Структура сущностей (app/entities/)

Каждая сущность имеет стандартную структуру:
```
entity_name/
├── __init__.py
├── model.py          # SQLAlchemy модель
├── repository.py     # Работа с БД
├── service.py        # Бизнес-логика
├── validator.py      # Валидация данных
└── api.py           # REST endpoints
```

### Ключевые компоненты

**Pages (Страницы)**
- Управляют состоянием страницы
- Загружают данные через custom hooks
- Организуют компоненты на странице

**Components (Компоненты)**
- Переиспользуемые UI элементы
- Modal — модальные окна для CRUD операций
- Forms — формы создания/редактирования с валидацией

**Hooks (Хуки)**
- Инкапсулируют логику работы с API
- Управляют состоянием (loading, error, data)
- Предоставляют методы для CRUD операций

### Визуализация расписания

**SchedulePage** реализует расширенный grid-based интерфейс:
- **Timeline** — горизонтальная шкала времени (9:00-18:00)
- **Строки** — кондитеры и оборудование отдельно
- **Блоки операций** — размещаются согласно времени выполнения
- **Статусы цветом** — планировано (серый), в процессе (жёлтый), завершено (зелёный)
- **Масштабирование** — zoom from 2x to 6x для удобства просмотра

## Системные требования и установка

### Требования
- **Node.js** 16+ (для frontend)
- **Python** 3.8+ (для backend)
- **PostgreSQL** 12+ (база данных)

### Установка и запуск

#### 1. Подготовка Backend

```bash
# Перейдите в корневую папку проекта
cd c:\Users\taima\PycharmProjects\Konditer_Plan

# Создайте виртуальное окружение (если не создано)
python -m venv .venv

# Активируйте виртуальное окружение
.venv\Scripts\activate

# Установите зависимости
pip install -r requirements.txt

# Запустите сервер
python -m uvicorn app.main:app --reload
```

Backend будет доступен на **http://localhost:8000**

#### 2. Подготовка Frontend

```bash
# Перейдите в папку frontend
cd frontend

# Установите зависимости
npm install

# Запустите приложение
npm start
```

Frontend будет доступен на **http://localhost:3000**

### Конфигурация БД

Отредактируйте строку подключения в `app/repositories/database.py`:

```python
DATABASE_URL = "postgresql://username:password@localhost:5432/confectionery"
```

Замените `username`, `password` и параметры подключения на ваши.

## Основной функционал

### 1. Управление заказами
- Создание новых заказов на определённые рецепты
- Редактирование заказов с автоматическим перепланированием
- Удаление заказов с очисткой расписания
- Отслеживание статуса: планируется → в процессе → завершено

### 2. Автоматическое планирование
- **PlanningService** анализирует заказы и доступные ресурсы
- Назначает операции на кондитеров и оборудование
- Соблюдает график работы (9:00-18:00)
- Учитывает требуемую квалификацию и тип оборудования

### 3. Управление ресурсами
- Кондитеры с разными уровнями квалификации
- Оборудование с типами (печь, миксер, и т.д.)
- Отслеживание загрузки ресурсов
- Предотвращение перегрузки

### 4. Управление складом
- Отслеживание остатков ингредиентов
- Визуализация низких запасов
- Управление минимальными нормами стока

### 5. Рецептуры
- Определение операций производства с последовательностью
- Указание требуемого оборудования и квалификации
- Список ингредиентов с норматив расходом

## API Endpoints

```
GET    /orders                    # Список всех заказов
POST   /orders                    # Создать заказ
PUT    /orders/{id}              # Обновить заказ
DELETE /orders/{id}              # Удалить заказ

GET    /recipes                   # Список рецептов
POST   /recipes                   # Создать рецепт
PUT    /recipes/{id}             # Обновить рецепт
DELETE /recipes/{id}             # Удалить рецепт

GET    /schedule                  # Расписание
POST   /schedule                  # Создать запись в расписание
DELETE /schedule/{id}             # Удалить запись

GET    /planning/run              # Запустить планирование
POST   /planning/run              # Запустить планирование для заказа

GET    /ingredients               # Список ингредиентов
GET    /inventories               # Запасы на складе

GET    /confectioners             # Список кондитеров
GET    /equipments                # Список оборудования
```

## Примечания для разработки

- Вся валидация данных выполняется на backend перед сохранением
- Удаление сущности автоматически удаляет связанные записи (cascade delete)
- Изменение заказа перетриггеривает перепланирование
- Frontend автоматически обновляет UI при ошибках API
- Все даты и времена хранятся в UTC в БД
